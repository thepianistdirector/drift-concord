# Drift Concord roadmap

This is a public planning repository. There is no product implementation or playable build yet. The image is an AI-generated vision reference, not a screenshot. All waves and tasks are proposed; no completed work, community approval or funding is implied.

The order reflects dependencies, not calendar commitments. Each wave advances only when its stated outcome is demonstrated and a maintainer accepts the next scope. Capacity targets are hypotheses to test.

## W1 — Every seat matters

Prove the crew loop with one expedition.

- **W1-T1: Script the derelict expedition.** Define preparation, discovery, salvage, a recoverable failure and the return home.
- **W1-T2: Prototype physical crew interactions.** Test piloting, power rerouting and handling salvage with minimal presentation.

## W2 — One ship that behaves consistently

Build the bounded systems needed by that mission.

- **W2-T1: Implement the ship systems model.** Connect power, propulsion, doors and damage through explicit state and limits.
- **W2-T2: Implement shared movement and objects.** Synchronize players and portable cargo in and around one moving ship.

## W3 — Bring the crew home

Deliver the first complete cooperative run.

- **W3-T1: Build the derelict and salvage objective.** Author one readable destination with meaningful navigation and cargo choices.
- **W3-T2: Run first-crew playtests.** Observe complete expeditions by groups unfamiliar with the design.

## W4 — Ships and stories persist

Add identity without turning play into compulsory upkeep.

- **W4-T1: Persist the ship and expedition journal.** Save configuration, cargo and completed expedition events with recoverable migrations.
- **W4-T2: Build the expedition authoring kit.** Describe locations, hazards, objectives and outcomes as inspectable mission packages.

## W5 — An open fleet of communities

Let independent operators host useful destinations.

- **W5-T1: Package community hosting and moderation.** Deliver host setup, access control, logs and a documented recovery procedure.
- **W5-T2: Prototype explicit sector handoff.** Design and test ownership transfer between two cooperating sector servers.

## W6 — A game worth returning to

Validate variety, performance and host workload.

- **W6-T1: Build a varied expedition pilot.** Add a bounded set of exploration, rescue and engineering missions using the kit.
- **W6-T2: Publish performance and operations findings.** Measure client performance, supported crew sizes, restoration and content moderation effort.
