# Validate a cooperative physical starship

Read the exact task revision and select the checks that address its acceptance criteria. This skill does not expand a task to the entire roadmap or authorize future implementation. These are validation instructions, not claims of an existing product.

1. Model the expedition as a crew trying to recover salvage and return together. Test each station with a missing crew member and show how a newcomer finds a useful action.

2. Separate authoritative ship state from local prediction. Exercise dropped/reordered updates, reconnects and two actors manipulating the same object; record corrections and divergence.

3. Track power, damage, oxygen and salvage through each agreed transition. Test a stalled subsystem and a failed repair without silently restoring resources.

4. For persistence and sector transfer, interrupt departure, receipt and acknowledgement. Demonstrate one recoverable ship state and unchanged crew ownership.

5. Playtest reports identify real crew size, session length, abandonment, coordination problems and motion discomfort. Performance reports state hardware, network conditions and actual client count.

For every selected check, record fixture/setup, actions, expected outcome, observed outcome and reproducible evidence. State which checks were not applicable and why; do not count unrun checks as passing.
